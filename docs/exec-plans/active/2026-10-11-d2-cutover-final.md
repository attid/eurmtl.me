# План перехода на d2 (cutover, вариант X — «режем под ноль»)

Статус: **в работе** (ГО владельца 2026-10-11). Предыдущий план:
`2026-10-07-d2-cutover.md` (план B — выполнен до фазы пилота).

## Текущее состояние (что уже работает в d2)

Создание `/d2/add` (черновик/публикация), экран `/d2/<uuid>` (правка, смена
чтений, автостатус `#next`, публикация/републикация), список с поиском и
фильтрами, воркспейсы PFM/GORA/USDMM/MTLA/TFM (`other/orgs_config.py`),
rich-посты с подвалом (`/d/<uuid>` в ссылке на правку), картинки через
`D2_IMAGES`, шаблоны, аудит-лог всех мутаций Grist. Данные в Grist:
1026 вопросов / 1805 чтений, номера per-org.

## Целевое состояние (после cutover)

- `/d` (GET+POST) — создание вопроса: роут d1 переименован в d2-механизм.
- `/d/<uuid>` (GET+POST) — экран/правка вопроса d2.
- `/d2/*` — остаются как алиасы (разосланные ссылки не умирают).
- **Удаляется целиком:** `cmd_add_decision` (GSpread+Postgres),
  `cmd_show_decision` (Postgres), `migrate_decisions_to_grist()` (одноразовая,
  выполнена), `other/gspread_tools.py` (Google Sheets), модель `Decisions`
  в `db/sql_models.py`, шаблон `tabler_decision.html`, хардкод `chat_ids`,
  `SP_USERS`/`SP_CHATS` конфиги старого дока, `/decision/number`.
- Владелец дропает таблицу `Decisions` в Postgres после чистки кода.

## Порядок (строгий, шаг = коммит, каждый шаг — рабочая система)

**Шаг 1. Алиас `/d/<uuid>` → d2-экран** — redirect на `/d2/<uuid>`.
Старые ссылки из д1-постов с d2-uuid оживают. ← ТЕКУЩИЙ ШАГ

**Шаг 2. Создание через `/d` → d2**: GET → редирект на `/d2/fragment/new`,
POST → прокси на d2-логику. `/decision/number` → удалить (дёргающих нет,
`_org_next_number` покрывает).

**Шаг 3. Резание d1** (один коммит «удаление легаси»): перечисленное в
«Целевом состоянии». Тесты d1 почистить.

**Шаг 4.** `/d2` → редирект `/d` (опционально; дешевле оставить оба).

**Шаг 5. Ночь (владелец):** деплой, приёмка, дроп `Decisions` в Postgres.

## Риски

- Rich-посты ссылаются на `/d/<uuid>`: до шага 1 они битые — шаг 1 первым.
- `d2_form.html` не трогать (санкционировано владельцем).
- Гонка номеров (`max+1`) — теоретическая; при коллизии «номер занят».
- Старые ссылки с д1-uuid (Postgres) → 404 после дропа таблицы — ожидаемо,
  архив не переносится.

## Чек-лист приёмки (финальной, владельцем)

1. Создание через `/d` (черновик) → правка → публикация → TG-пост с подвалом,
   клик по ссылке правки открывает экран.
2. Смена чтения → старый пост получил `#next` + ссылку на новое чтение.
3. Картинка в теле → видна в TG.
4. Шаблон → создание из шаблона.
5. Деплой → дроп `Decisions`.
