# 2026-11-04 — D2: подвал поста (хвост, self-link, одна строка) + 1:1 тема в редакторе

Жалобы владельца/юзеров, собранные в один заход. Принцип, зафиксированный
владельцем: **текст в TG = текст в редакторе 1:1; добавляться могут только
управляющие штуки** (статус-строка с тегом чтения, подвал ссылок, Edit on
eurmtl.me, Added by). Любое авто-добавление содержательного текста в пост —
нарушение идеи.

## Задачи

### 1. Пропавший хвост при смене чтения

`cmd_d2_show` POST, ветка «смена чтения» (routers/decision.py:726):
`_d2_send_rich` вызывается без `links_url` / `uuid_url` / `username` —
дефолты `([], [], [])` → rich-пост нового чтения публикуется без подвала
вообще (ни ссылок чтений, ни Edit, ни Added by). Legacy-фолбэк и правка
старого поста хвост передают — баг только в rich-отправке нового поста.

Фикс: дополнить вызов `links_url=links_url, uuid_url=new_uuid,
username=username`.

### 2. Без self-link

Пост чтения N не содержит ссылку на чтение N («мы же там находимся»,
решение владельца). Сегодня self-link лезет из `_question_links` (возвращает
ссылки ВСЕХ чтений, включая текущее) в трёх местах: правка published-чтения
(669/681), правка старого поста при смене чтения (827), publish/републикация
(959/977/990; там же — мёртвая ссылка на удалённый пост). Следствие: вопрос
с единственным чтением — подвал вообще без ссылок на чтения.

Фикс: фильтрация слота `reading-1` внутри билдеров подвала, не в links_url:

- `_d2_rich_blocks` — в цикле подвала пропускать индекс `reading-1`
  (reading уже приходит параметром);
- `get_full_text` — добавить параметр `reading`, пропускать свой слот;
  проставить в вызовах: `:669` → `new_reading`, `:721` → `new_reading`,
  `:990` → `reading` (`:1178` — пустые ссылки, симметрично можно тоже).

### 3. Ссылки чтений одной строкой через `|`

Было (каждая на своей строке):

```
---
Первое чтение
Третье чтение
-
Edit on eurmtl.me
Added by @user
```

Станет (решение владельца):

```
---
Первое чтение | Третье чтение
-
Edit on eurmtl.me
Added by @user
```

- склейка непустых слотов (после фильтрации self-link) через ` | `;
- ссылок нет → строка не выводится вовсе (`---` / `-` / Edit / Added by
  остаются);
- rich: один `<p>` с текстовыми вставками ` | ` между `<a>` (конвертер
  умеет inline-смесь текста и ссылок в одном параграфе);
- legacy `get_full_text`: та же склейка вместо трёх append'ов.

### 5. 1:1 редактор→TG: вычистить «Вопрос N: Тема» из рендерера

Prefix-ветка `_d2_rich_blocks` (MTLA/RELY, `decision.py:286`) сама
дописывает в пост жирную строку «Вопрос N: Тема», склеенную с телом без
перевода строки («...уставПредлагаю» — реализация не соответствовала
замыслу «ниже», решение владельца 2026-10-10). По принципу 1:1 это
нарушение: авто-добавление содержательного текста.

Фикс: из prefix-ветки убрать `{num}{title}`-вставку. Формат MTLA/RELY
после чистки: `<статус> #<N>_reading>` / BODY как в редакторе / подвал.

**Остаются** (управляющие штуки, подтверждено владельцем): тег
`#first_reading` и compagnie в статус-строке MTLA/RELY; статус-строка;
подвал. Пункт «склейка MTLA» отпадает сам — вместе со строкой исчезает.

### 5a. UX: тема → тело, живой слепок вместо ручной лупы

Жалоба: «тема не попадает в тело». Лупа (`#loadsDecisionNum` →
`getNumber()`, templates/d2_form.html) делает это ручным кликом; в d2
номер предзаполнен → лупу не жмут → строки нет. Плюс баг: 3 клика по лупе
= 3 дубля «Вопрос N:» в теле.

Решение (согласовано с владельцем):

- строка «Вопрос N: Тема» — живой слепок поля «Тема» в теле редактора:
  - **debounce ~0.5s** после прекращения набора (не на каждый символ, не
    по blur);
  - финальный sync перед сабмитом;
- **лупа остаётся**, её роль — обновить номер (fetch `/d2/number`);
  подстановку тела из лупы удалить → дублей физически не остаётся;
- правило владения строкой:
  - владеем только первой строкой тела;
  - на загрузке: первая строка под паттерн `Вопрос <число>: …` →
    перехватываем в синхронизацию (старые шаблоны с запечённой строкой
    свежеют), иначе вставляем строку сверху;
  - в сессии: юзер поправил/удалил первую строку руками → владение
    снято, тело больше не трогаем (ручные правки не теряем);
- пустая тема на загрузке: строка висит как «Вопрос 5: », заполняется
  по мере набора (тема обязательна — пустой не уйдёт);
- шаблоны: TITLE шаблона показывается в шапке («Шаблон: …»), поле темы
  остаётся пустым для ввода юзером — строка-слепок висит как «Вопрос 5: »
  и заполняется по мере набора; тело без строки → вставка сверху; тело с
  запечённой строкой → п. «на загрузке»;
- **синхронизация только на форме нового вопроса** (`d2_form.html`).
  Экран редактирования существующего вопроса и MCP-черновики — тело
  историческое, «как есть» (1:1), не трогаем.

### Реализация слепка

JS в `d2_form.html` (или включаемый сниппет рядом с quill-include, без
отдельного статического файла — кеш-бастинг не нужен): input-listener на
`#short_subject` + `#question_number` (лупа меняет номер → строка
пересоберётся), Quill Delta для правки первой строки. Паттерн строки в
BODY: `<b>Вопрос <N>: <тема></b>` первой строкой.
